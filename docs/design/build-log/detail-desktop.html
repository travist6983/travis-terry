##The problem

Coding agents tend to fail the same way, and it’s rarely the model’s fault. The agent reads a bug, makes a change, sees something green and says it’s done. When it’s wrong, it tries the same idea again in different words. When it’s right, nothing it learned carries over to the next ticket.

A smarter model doesn’t fix that. The system around the model has to know what “done” means, notice why an attempt failed, and remember what worked.

##What the kit did

Every agent in the kit is a loop, not a prompt: a thin recipe that strings small skills together, with a gate between every step and a written contract for what each step hands to the next. The reference loop is the defect loop:

The evaluator comes first. Before anything gets fixed, the repro step writes a replay script that has to fail on the broken build. Later, verify runs that same script, and it has to flip from red to green.

##What broke, and what I changed

Five failures from the commit history. None of them failed loudly, so every fix turns a quiet failure into a loud one.

##What’s still unproven

Every production loop stays dry run and staging only until four safety gates exist in the stack it runs against. The onboarding quiz’s pass marks are starting numbers too, not measured ones.

$ git commit -m The model doesn’t learn anything between runs. The loop around it does.

##Try it

Start with docs/loop-engineering.md in agent-kit. It’s the rubric every skill is held to, and it’s a lot shorter than the code.
